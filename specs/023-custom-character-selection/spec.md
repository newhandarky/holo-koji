# Feature Specification: Custom Character Selection

**Feature Branch**: `023-custom-character-selection`  
**Created**: 2026-05-05  
**Status**: Implemented  
**Input**: User description: "023-custom-character-selection"

## Clarifications

### Session 2026-05-05

- Q: Custom-selected room 的 rematch 要如何處理自訂角色與 board position？ → A: Rematch 沿用同一組自訂 7 位角色，但每次 rematch 可重新隨機分配 board position。
- Q: 自訂選角時，房主要不要也能指定每位角色的 board position？ → A: 房主只選 7 位角色；board position 由系統依既有規則隨機分配。
- Q: 如果目前某個角色組合剛好只有 7 位可用角色，自訂選角模式要怎麼呈現？ → A: 角色池剛好 7 位時，自訂模式預設全選 7 位，房主可直接建立房間。

## User Scenarios & Testing

### User Story 1 - Choose the seven board characters during room creation (Priority: P1)

A room creator chooses one supported character set, reviews the available characters in that set, and manually selects exactly seven characters for the match before creating the room. The match then starts with those seven selected characters assigned to the normal seven board positions by the system.

**Why this priority**: This is the core value of the feature. It lets players control which character identities appear while preserving the existing seven-position game structure.

**Independent Test**: Create online and NPC rooms from each supported character set with a custom seven-character selection and confirm the generated board uses exactly those seven unique characters from the selected set while board positions are assigned by the existing system rules.

**Acceptance Scenarios**:

1. **Given** a room creator selects Ginza and chooses seven Ginza characters, **When** the room is created, **Then** the board contains exactly those seven Ginza characters.
2. **Given** a room creator selects 擅自合作系列 and chooses seven 擅自合作系列 characters, **When** the room is created, **Then** the board contains exactly those seven 擅自合作系列 characters.
3. **Given** a room creator selects Hololive and chooses seven Hololive characters, **When** the room is created, **Then** the board contains exactly those seven Hololive characters.
4. **Given** the selected character set has exactly seven available characters, **When** the room creator enables custom selection, **Then** all seven characters are preselected and the creator can create the room without extra selection steps.
5. **Given** the room creator has selected fewer or more than seven characters, **When** they try to create the room with custom selection enabled, **Then** the room is not created and the creator receives a clear correction path.

---

### User Story 2 - Keep random setup available when custom selection is not used (Priority: P1)

A room creator who does not want to choose individual characters can create a room exactly as before. The system still selects seven characters from the chosen set using the existing random setup rule.

**Why this priority**: Custom selection must not add required setup work for players who prefer quick room creation.

**Independent Test**: Create online and NPC rooms without choosing custom characters and confirm the resulting board follows the existing random seven-character selection behavior.

**Acceptance Scenarios**:

1. **Given** a room creator selects a character set and leaves custom selection unused, **When** the room is created, **Then** the board is generated by the existing random selection rule.
2. **Given** a supported set currently contains exactly seven available characters, **When** random setup is used, **Then** all seven are still eligible and board placement may differ between matches.
3. **Given** a supported set later contains more than seven available characters, **When** random setup is used, **Then** seven are selected from the complete available pool.

---

### User Story 3 - Preserve shared room identity for joiners and rematches (Priority: P2)

Players joining the room see the same selected seven characters chosen by the creator. Rematches in the same room keep the creator's custom character selection unless the creator starts a new room setup flow, while each rematch may reassign those seven characters to board positions.

**Why this priority**: Custom selection is part of room setup. All players must share the same board identity to avoid disagreement about scoring, item ownership, or displayed characters.

**Independent Test**: Create a custom-selected room, join it from a second player, and confirm both players receive the same selected board. Request a rematch and confirm the same custom-selected character set is reused while board position assignment may differ.

**Acceptance Scenarios**:

1. **Given** a room was created with a custom seven-character selection, **When** another player joins, **Then** the joiner sees the same seven characters and board positions as the creator.
2. **Given** a custom-selected room enters a rematch, **When** the new match setup begins, **Then** the same selected seven characters are reused and may be reassigned to different board positions.
3. **Given** a room was created with random setup, **When** a rematch begins, **Then** the existing random setup behavior remains unchanged.

---

### User Story 4 - Reject invalid or stale custom selections safely (Priority: P2)

If a custom selection includes characters outside the selected set, duplicate characters, unavailable characters, or stale character identities, the room is not created or restored from that invalid selection.

**Why this priority**: Custom selection introduces user-provided board identity. Invalid selections must fail safely and must not fall back to hidden or mismatched character data.

**Independent Test**: Attempt to create or restore rooms with invalid custom selections and confirm the system rejects them with a clear user-facing recovery path.

**Acceptance Scenarios**:

1. **Given** a creator submits duplicate character identities, **When** they try to create the room, **Then** the room is rejected and no fallback board is created.
2. **Given** a creator submits a character from a different set, **When** they try to create the room, **Then** the room is rejected and no mixed-set board is created.
3. **Given** a saved custom-selected room references a character that is no longer available, **When** restoration is attempted, **Then** restoration is rejected with a recovery path.

## Requirements

### Functional Requirements

- **FR-001**: The room creator MUST be able to choose between random setup and custom character selection during room creation.
- **FR-002**: Custom character selection MUST be limited to one selected character set at a time.
- **FR-003**: A custom-selected room MUST require exactly seven selected characters before room creation can complete.
- **FR-004**: The seven selected characters MUST be unique.
- **FR-005**: Every selected character MUST belong to the room's selected character set and be currently available.
- **FR-006**: If custom selection is not used, room creation MUST follow the existing random seven-character setup rule.
- **FR-007**: The generated board MUST still contain exactly seven board positions.
- **FR-008**: Item cards, item icons, charm values, action rules, scoring, and win conditions MUST remain bound to board-position rules rather than character identity.
- **FR-009**: Room joiners MUST receive the creator's selected character set and selected board characters.
- **FR-010**: Rematches in a custom-selected room MUST reuse the same selected seven-character pool unless the creator starts a new room setup flow, and MAY reassign those characters to different board positions.
- **FR-011**: Invalid, duplicate, cross-set, unavailable, or stale custom selections MUST be rejected rather than repaired with fallback characters.
- **FR-012**: Room restoration MUST reject saved custom selections that no longer validate against the selected character set.
- **FR-013**: Custom selection MUST NOT expose opponent hands, secret choices, pending choices, removed cards, or unrevealed action details.
- **FR-014**: Custom selection MUST NOT add, remove, or rename supported character set choices.
- **FR-015**: The feature MUST preserve the existing online and NPC room creation flows for players who do not use custom selection.
- **FR-016**: Custom selection MUST NOT let the room creator assign selected characters to specific board positions.
- **FR-017**: When a selected character set has exactly seven available characters, custom selection mode MUST preselect all seven characters and allow room creation without requiring manual selection steps.

### Non-Functional Requirements

- **NFR-001**: Players who use custom selection MUST be able to understand how many more characters must be selected before room creation is allowed.
- **NFR-002**: Invalid custom selection errors MUST provide a clear recovery path without exposing technical data internals.
- **NFR-003**: The custom selection flow MUST remain usable on mobile-sized screens without requiring a separate desktop-only workflow.
- **NFR-004**: The feature MUST remain maintainable when character pools grow beyond seven profiles.

### Key Entities

- **Character Set**: A supported selectable group such as Ginza, 擅自合作系列, or Hololive.
- **Character Profile**: A stable character identity with display name and image data.
- **Custom Selection**: The creator-chosen list of exactly seven unique character identities from one character set; it does not include board-position assignment.
- **Selected Board Cast**: The seven characters used by one room or match after random or custom setup.
- **Board Position**: One of the seven fixed gameplay positions that owns charm value and item/icon behavior independently of character identity.
- **Room Setup**: The creator's setup choices, including selected character set, random/custom setup mode, and custom selection when used.
- **Room Snapshot**: Saved room state containing the selected setup mode, selected character set, and selected board cast.

## Success Criteria

- **SC-001**: 100% of custom-selected room creation attempts with exactly seven valid unique characters produce a board containing those seven characters.
- **SC-002**: 100% of custom-selected room creation attempts with fewer than seven, more than seven, duplicate, cross-set, unavailable, or stale characters are rejected before a broken room is created.
- **SC-003**: 100% of joiners in custom-selected rooms see the same selected seven characters as the room creator.
- **SC-004**: 100% of custom-selected boards preserve the existing seven board-position charm values and item/icon associations.
- **SC-005**: Players can still create online and NPC rooms without custom selection through the existing random setup flow.
- **SC-006**: On mobile-sized screens, players can complete custom selection for a room without losing visibility of selection count or room creation readiness.
- **SC-007**: Restored custom-selected rooms either validate the saved seven-character selection or fail with a recovery path.
- **SC-008**: When a selected character set has exactly seven available characters, players can enable custom selection and create the room without performing seven manual selection actions.

## Assumptions

- The room creator is the only player who chooses a custom selection during room creation.
- Custom selection happens before the room is created; joiners do not modify the selected character list.
- If a supported character set currently has exactly seven available characters, custom selection preselects all seven and is equivalent in roster to random setup, while still preserving the creator's explicit setup mode.
- Board position charm distribution and item/icon associations remain the existing source of truth.
- The feature builds on the 022 rule that every board contains exactly seven characters selected from one supported set.

## Out of Scope

- Letting joiners vote on or change the creator's custom selection.
- Choosing fewer or more than seven board characters.
- Mixing characters from multiple character sets in one room.
- Adding new character sets beyond Ginza, 擅自合作系列, and Hololive.
- Changing item card data, item icons, charm distribution, scoring, actions, turn order, or win conditions.
- Building collection, account, achievement, unlock, ban, draft, or favorite-list systems for individual characters.
