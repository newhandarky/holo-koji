# Feature Specification: 拿取開局手牌與翻面揭示

**Feature Branch**: `029-take-opening-hand-reveal`  
**Created**: 2026-05-06  
**Status**: Draft  
**Input**: User description: "029-take-opening-hand-reveal"

## Clarifications

### Session 2026-05-06

- Q: 拿取手牌狀態是否需要跨重新整理/重連保存？ → A: 不跨重整保存；重新整理或重連後，若仍符合開局拿取條件，可以重新看到「拿取手牌」流程，但不重發牌、不改變牌權。
- Q: 揭示動畫期間要阻擋哪些操作？ → A: 只阻擋手牌選取與手牌指令；玩家仍可切換非破壞性的 UI 區塊，但不能觸發任何對局行動。
- Q: 什麼狀態才算「符合開局拿取條件」？ → A: 只在開局發牌已完成、玩家自己手牌仍是起始 6 張、且尚未進行任何會改變手牌或行動狀態的操作時顯示。
- Q: 拿取後的手牌揭示要如何呈現？ → A: 依手牌目前排序逐張翻面揭示；reduced motion 可直接顯示完成狀態。
- Q: 揭示完成後要如何處理目前 UI 區塊？ → A: 揭示完成後一律切換或聚焦到 `手牌&指令` 區域。
- Q: 如何判定已發生會改變手牌或行動狀態的操作？ → A: 以前端可見狀態判定；若目前玩家曾使用任一行動標記、存在 pending interaction、手牌張數不是 6、或遊戲 phase 不是 playing，則視為不符合開局拿取條件。

## User Scenarios & Testing

### User Story 1 - 拿取並揭示自己的開局手牌 (Priority: P1)

玩家在開局發牌演出完成後，不會立刻看到自己的起始手牌正面，而是先看到明確的「拿取手牌」狀態。玩家按下控制後，自己的起始手牌才會依目前手牌排序逐張翻面揭示；揭示完成後，畫面一律切換或聚焦到可查看手牌與指令的對局區域。

**Why this priority**: 這是 029 的核心體驗；若玩家在開局發牌後立即看到手牌，028 與 029 之間預期的「拿取手牌」儀式與資訊揭示節奏就不存在。

**Independent Test**: 建立新對局並完成開局發牌演出後，確認自己的起始手牌在按下「拿取手牌」前不顯示正面資訊；按下後，自己的起始手牌以揭示效果出現，並切換到手牌與指令區域。

**Acceptance Scenarios**:

1. **Given** 開局發牌演出已完成、玩家自己的手牌仍是起始 6 張、且尚未進行任何會改變手牌或行動狀態的操作，**When** 玩家回到對局畫面，**Then** 系統顯示「拿取手牌」狀態，且自己的手牌仍以遮蔽狀態呈現。
2. **Given** 玩家尚未拿取開局手牌，**When** 玩家查看手牌區域，**Then** 玩家只能看到卡背、占位或張數資訊，不會看到任何手牌正面資料。
3. **Given** 玩家按下「拿取手牌」，**When** 揭示流程執行，**Then** 自己的起始手牌會依目前手牌排序逐張翻面揭示，且卡牌數量、順序與身分不因呈現流程而改變。
4. **Given** 揭示流程完成，**When** 玩家繼續對局，**Then** 畫面一律導向或聚焦到 `手牌&指令` 區域，且玩家可以依既有合法規則進行操作。

---

### User Story 2 - 揭示前保護資訊並阻擋過早操作 (Priority: P2)

玩家在拿取手牌前不應透過畫面、可點擊元素、輔助文字或快捷操作提前得知自己的起始手牌內容，也不能在揭示完成前透過手牌選取或指令觸發實際對局行為。揭示期間可保留非破壞性的 UI 區塊導覽，但不得允許任何手牌選取、手牌指令或對局行動被觸發。

**Why this priority**: 這個流程雖然主要是玩家自己的資訊揭示，但仍必須避免 UI 以文字、圖片、可及性標籤或互動狀態提前破壞揭示體驗，並避免動畫期間造成非法或重複操作。

**Independent Test**: 在拿取前檢查畫面與可操作元素，確認自己的手牌正面資訊不可見且手牌相關操作不可觸發；揭示完成後再檢查操作可用性回到既有合法規則。

**Acceptance Scenarios**:

1. **Given** 玩家尚未拿取開局手牌，**When** 玩家嘗試選取手牌或使用需要手牌的指令，**Then** 系統不會觸發手牌選取或指令行為。
2. **Given** 揭示動畫正在執行，**When** 玩家切換非破壞性的 UI 區塊，**Then** 系統可以保留導覽回應，但仍不得觸發手牌選取、手牌指令或任何對局行動。
3. **Given** 揭示動畫正在執行，**When** 玩家連續點擊或使用鍵盤操作手牌區域，**Then** 系統不會重複揭示、重複觸發行動或改變 server 權威狀態。
4. **Given** 揭示流程已完成，**When** 玩家操作手牌或指令，**Then** 可用性完全依目前回合、行動鎖與既有規則判定。

---

### User Story 3 - 在中斷、低動態與非開局狀態下保持正確 (Priority: P3)

玩家若偏好減少動態、重新整理、重連，或回到已經不再是開局起始手牌狀態的對局，系統仍應以目前合法對局狀態為準，不得重發牌、複製牌、揭露隱藏資訊或阻擋已進行中的對局。符合開局拿取條件代表開局發牌已完成、遊戲 phase 是 playing、玩家自己的手牌仍是起始 6 張、目前玩家尚未使用任一行動標記，且不存在 pending interaction。

**Why this priority**: `拿取手牌` 是呈現層流程，不能破壞重連恢復、可及性或既有 server authoritative 對局狀態。

**Independent Test**: 分別在 reduced motion、刷新重連、以及對局已進行後回到房間的情境檢查，確認流程不會造成卡牌重複、不會重置對局，也不會阻擋目前合法狀態。

**Acceptance Scenarios**:

1. **Given** 玩家偏好減少動態效果，**When** 玩家按下「拿取手牌」，**Then** 系統可以直接顯示完成狀態並呈現自己的起始手牌。
2. **Given** 玩家重新整理或重連且開局發牌已完成、遊戲 phase 是 playing、自己的手牌仍是起始 6 張、目前玩家尚未使用任一行動標記且不存在 pending interaction，**When** 玩家回到對局，**Then** 系統可以重新呈現本地拿取流程，因為拿取狀態不跨重整保存；但不得重新發牌、改變牌權或產生新隱藏牌。
3. **Given** 對局已不再符合開局拿取條件，**When** 玩家進入或回到對局，**Then** 系統跳過「拿取手牌」閘門並顯示目前合法可見狀態。

## Requirements

### Functional Requirements

- **FR-001**: 開局發牌演出完成後，若遊戲 phase 是 playing、玩家自己的手牌仍是起始 6 張、目前玩家尚未使用任一行動標記且不存在 pending interaction，系統必須先顯示「拿取手牌」狀態，再顯示自己的手牌正面。
- **FR-002**: 玩家按下「拿取手牌」前，自己的起始手牌必須只以卡背、占位、遮蔽狀態或張數資訊呈現，不得顯示卡牌識別、藝妓、魅力值、圖片、文字標籤或任何可推測卡面內容的資訊。
- **FR-003**: 系統必須提供清楚可啟用的「拿取手牌」控制，讓玩家主動開始自己的開局手牌揭示流程。
- **FR-004**: 「拿取手牌」控制必須支援滑鼠、觸控與鍵盤啟用。
- **FR-005**: 玩家啟用「拿取手牌」後，系統必須依目前手牌排序逐張翻面揭示自己的起始手牌；reduced motion 模式可以直接顯示完成狀態。
- **FR-006**: 揭示後顯示的手牌必須與目前合法對局狀態中的玩家手牌一致，不得因呈現流程改變卡牌數量、順序、身分、所有權或可用性。
- **FR-007**: 揭示完成後，系統必須一律導向或聚焦到 `手牌&指令` 區域，讓玩家清楚知道接下來可以查看手牌與可用指令。
- **FR-008**: 玩家尚未完成拿取與揭示流程前，系統不得允許手牌選取、手牌指令或任何對局行動被觸發；揭示期間可以保留非破壞性的 UI 區塊導覽。
- **FR-009**: 揭示流程期間，系統必須避免重複啟動、重複揭示、重複手牌操作或任何可能改變 server 權威狀態的副作用。
- **FR-010**: 揭示完成後，手牌與指令可用性必須完全依既有回合、行動鎖、玩家身分與遊戲規則判定。
- **FR-011**: 本功能不得揭露對手手牌、隱藏保留牌、牌堆內容、待處理選擇、未公開結算資訊或任何玩家不應看到的隱藏資訊。
- **FR-012**: 本功能不得改變 server 開局發牌、移除牌、牌權、先後手、抽牌、得分、結算或勝負判定。
- **FR-013**: 偏好減少動態效果的玩家必須能以直接完成狀態完成拿取手牌流程，且資訊完整性與一般逐張翻面揭示流程相同。
- **FR-014**: 若目前狀態已不符合開局拿取條件，包含遊戲 phase 不是 playing、手牌不再是起始 6 張、目前玩家已使用任一行動標記、或存在 pending interaction，系統必須跳過拿取手牌閘門並顯示目前合法可見的對局狀態。
- **FR-015**: 玩家重新整理或重連時，拿取手牌狀態不需要跨重整保存；若開局發牌已完成、遊戲 phase 是 playing、自己的手牌仍是起始 6 張、目前玩家尚未使用任一行動標記且不存在 pending interaction，系統可以重新呈現本地拿取流程，但不得重新發牌、複製手牌、改變牌權或洩漏隱藏資訊。
- **FR-016**: 本功能必須維持手機優先的對局布局與底部區塊導覽慣例，且不得造成主要文字、控制項或手牌顯示重疊。
- **FR-017**: 本功能不得新增 skip button、改變開局發牌 modal、調整回合抽牌通知、改版結算畫面或修改大廳 AI 難度文字。

### Non-Functional Requirements

- **NFR-001**: 一般動態模式下，拿取後的手牌揭示呈現應在 3 秒內完成。
- **NFR-002**: Reduced motion 模式下，拿取後的手牌揭示應在 1 秒內完成或直接顯示完成狀態。
- **NFR-003**: 揭示前遮蔽狀態必須預設保護資訊，新增視覺樣式或輔助文字時不得需要讀取或輸出手牌正面資訊。
- **NFR-004**: 「拿取手牌」控制與揭示完成後的 `手牌&指令` 入口必須在手機與桌面尺寸中清楚可達。
- **NFR-005**: 本功能應以本地呈現狀態為主，不得讓視覺流程成為 server 規則狀態推進的必要條件。

### Key Entities

- **拿取手牌閘門**: 開局發牌演出完成後、自己的手牌正面顯示前的玩家主動確認狀態。
- **遮蔽開局手牌**: 玩家自己的起始手牌在拿取前的安全呈現，只表達持有張數或牌背，不包含正面資訊。
- **手牌揭示呈現**: 玩家按下「拿取手牌」後，依目前手牌排序逐張將自己的起始手牌從遮蔽狀態轉為可見狀態的視覺流程；reduced motion 可直接完成。
- **本地揭示記憶**: 用於判斷目前畫面工作階段是否已完成拿取流程的呈現狀態，不代表 server 規則狀態。
- **手牌與指令焦點**: 揭示完成後一律導向玩家查看手牌與可用指令的對局區域。

## Success Criteria

- **SC-001**: 100% 開局發牌已完成、遊戲 phase 是 playing、玩家自己的手牌仍是起始 6 張、目前玩家尚未使用任一行動標記且不存在 pending interaction 的新對局，在自己的起始手牌正面顯示前都會先顯示「拿取手牌」狀態。
- **SC-002**: 100% 拿取前畫面不顯示自己的起始手牌卡牌識別、藝妓、魅力值、圖片或文字標籤。
- **SC-003**: 100% 拿取並揭示完成後，玩家看到的起始手牌張數、順序與身分都與目前合法對局狀態一致，且一般動態模式依目前手牌排序逐張揭示。
- **SC-004**: 100% 揭示前或揭示中的手牌選取、手牌指令與對局行動不會被觸發；非破壞性的 UI 區塊導覽不受此限制。
- **SC-005**: 至少 95% 一般逐張揭示流程可在 3 秒內完成；reduced motion 情境下 100% 可在 1 秒內完成或直接完成。
- **SC-006**: 重新整理或重連測試中，100% 不會出現重新發牌、手牌複製、牌權改變或隱藏資訊洩漏。
- **SC-007**: 在測試的手機與桌面尺寸中，「拿取手牌」控制、遮蔽手牌、揭示後手牌與完成後一律聚焦的 `手牌&指令` 區域皆可辨識且沒有主要元素重疊。

## Assumptions

- 028 已完成開局發牌 modal，並在 modal 自動關閉後回到目前合法可見的對局畫面。
- 029 是玩家端呈現流程；玩家自己的手牌在 server 權威狀態中已合法存在，不需要新的發牌或確認事件。
- 本地拿取狀態不跨重新整理或重連保存；回到對局後可以重新呈現，但必須以目前合法對局狀態為準。
- 若對局已進行到不再是起始 6 張手牌、目前玩家已使用任一行動標記、存在 pending interaction，或 game phase 已不是 playing，恢復目前合法對局狀態優先於強制補播拿取流程。
- Skip button 與可手動跳過動畫的控制會由後續動畫控制規格另行處理。

## Out of Scope

- 改變 server authoritative 開局牌務、移除牌、手牌分配、先後手或勝負規則。
- 新增 server 端「已拿取手牌」狀態、socket event 或確認 ACK。
- 新增 skip button 或定義 skip 後流程。
- 改變 028 開局發牌 modal、卡背主題或開局發牌順序呈現。
- 揭露或呈現對手手牌。
- 調整回合開始抽牌通知與抽牌焦點。
- 設計或改版結算畫面。
- 調整大廳 AI 難度文字。
