# Feature Specification: 開局發牌動畫 Modal

**Feature Branch**: `028-opening-deal-animation-modal`  
**Created**: 2026-05-06  
**Status**: Draft  
**Input**: User description: "028-opening-deal-animation-modal"

## Clarifications

### Session 2026-05-06

- Q: 開局發牌 modal 播放完成後，應該如何結束並回到對局畫面？ → A: 動畫完成後自動關閉 modal，回到目前合法可見的對局畫面。
- Q: 開局發牌 modal 播放期間，玩家是否可以操作 modal 後方的對局 UI？ → A: Modal 播放期間阻擋後方 UI 操作；動畫完成自動關閉後才恢復操作。
- Q: 玩家在開局發牌 modal 自動關閉前重新整理或重連，且安全開局進度仍可重播時，應該如何恢復？ → A: 若安全開局進度仍可重播，重連後從頭播放開局發牌 modal。
- Q: 在 028 完成後、但 029 `拿取手牌` 尚未實作前，開局發牌 modal 自動關閉後玩家自己的起始手牌是否可以依現有合法狀態顯示在手牌區？ → A: 可以；modal 關閉後維持現有合法可見對局畫面，玩家自己的手牌可照目前流程顯示。

## User Scenarios & Testing

### User Story 1 - 觀看安全的開局發牌演出 (Priority: P1)

玩家在雙方確認先後順序並進入對局時，會看到一個專用開局發牌畫面：中央牌堆先移出一張未知牌到保留位置，接著依先後順序逐張把背面牌發到雙方方向。整個過程讓玩家理解開局牌務已完成，但不顯示任何未揭露卡面。

**Why this priority**: 這是 028 的核心價值；若玩家看不到安全且清楚的開局發牌演出，後續 `拿取手牌` 與手牌翻面流程就缺少前置儀式感。

**Independent Test**: 建立新對局並完成先後順序確認後，檢查玩家會看到開局發牌 modal，動畫順序包含 1 張未知保留牌、雙方各 6 張背面起始手牌，以及完成狀態；畫面與可見資料都不包含卡牌正面內容。

**Acceptance Scenarios**:

1. **Given** 雙方已完成先後順序確認且 server 已提供安全開局進度，**When** 玩家進入對局畫面，**Then** 系統顯示開局發牌 modal。
2. **Given** 開局發牌 modal 顯示中，**When** 發牌演出開始，**Then** 玩家會先看到一張背面牌從中央牌堆移到保留位置。
3. **Given** 保留牌演出完成，**When** 起始手牌演出進行，**Then** 玩家會看到背面牌依先手第 1 張、後手第 1 張的順序輪流發到雙方方向，直到雙方各 6 張。
4. **Given** 開局發牌 modal 顯示中，**When** 玩家嘗試操作 modal 後方的對局 UI，**Then** 後方 UI 不會接收操作。
5. **Given** 發牌演出完成，**When** modal 自動關閉，**Then** 玩家回到目前合法可見的對局畫面，且不因動畫完成而改變 server 規則狀態或既有手牌顯示流程。

---

### User Story 2 - 使用一致且可替換的卡背 (Priority: P2)

玩家在開局發牌演出中會看到符合目前銀座夜間風格的預設卡背。卡背看起來像正式遊戲牌背，不會與角色卡面或道具卡面混淆，且未來可以替換或擴充不同主題。

**Why this priority**: 發牌動畫所有牌都以背面呈現，卡背品質直接影響玩家是否能理解這是正式開局流程，而不是錯誤或暫時 placeholder。

**Independent Test**: 在預設角色組合的新對局中檢查開局 modal，確認中央牌堆、保留牌與發出的背面牌都使用同一套預設卡背，且畫面沒有出現任何角色或道具正面資訊。

**Acceptance Scenarios**:

1. **Given** 開局發牌 modal 顯示中，**When** 任一張牌以背面呈現，**Then** 玩家看到一致的預設卡背視覺。
2. **Given** 玩家正在觀看卡背，**When** 卡背與角色卡或道具卡同時出現在遊戲中，**Then** 玩家可以清楚分辨卡背不是任何已揭露卡面。
3. **Given** 未來需要替換卡背主題，**When** 規劃新主題，**Then** 不需要重新定義開局發牌規則或隱藏資訊規則。

---

### User Story 3 - 在低動態或中斷情境下仍能理解流程 (Priority: P3)

玩家如果偏好減少動畫，或在開局期間重新整理、斷線後回到房間，仍能看到安全且可理解的開局狀態。系統不會因動畫沒有完整播放而重發牌、重移除牌或揭露未公開內容。

**Why this priority**: 開局動畫是呈現層，不能破壞可及性、重連恢復或 server authoritative 狀態。

**Independent Test**: 在 reduced motion 與重連情境下進入新對局，確認玩家會看到短版或完成狀態的開局呈現，且不會看到移除牌、對手手牌或牌堆內容。

**Acceptance Scenarios**:

1. **Given** 玩家偏好減少動態效果，**When** 開局發牌 modal 顯示，**Then** 系統使用短版、低位移或直接完成狀態呈現同一個開局順序。
2. **Given** 玩家在開局發牌演出期間重新整理或重連，且安全開局進度仍可重播，**When** 玩家回到房間，**Then** 系統從頭播放開局發牌 modal，且不重新移除牌或重新發牌。
3. **Given** 開局進度已標記不再重播，**When** 玩家重連回到房間，**Then** 系統不強制重播完整開局動畫，並直接顯示目前合法可見的對局狀態。

## Requirements

### Functional Requirements

- **FR-001**: 系統必須在新對局完成先後順序確認且取得安全開局進度後，顯示開局發牌 modal。
- **FR-002**: 開局發牌 modal 必須呈現中央牌堆、單張隱藏保留牌位置、先手玩家方向與後手玩家方向。
- **FR-003**: 開局發牌流程必須先呈現 1 張背面牌移至隱藏保留位置，再呈現雙方起始手牌發牌流程。
- **FR-004**: 起始手牌發牌呈現必須依已確認的先後順序輪流顯示：先手第 1 張、後手第 1 張，重複直到雙方各 6 張。
- **FR-005**: 開局發牌 modal 中所有發牌與保留牌都必須以背面呈現，不得顯示卡牌識別、角色、道具、魅力值、圖片或任何可推測卡面內容的資訊。
- **FR-006**: 開局發牌 modal 不得要求 server 等待動畫完成才允許規則狀態進入可操作狀態；動畫只影響玩家介面呈現。
- **FR-007**: 開局發牌 modal 必須在發牌演出完成後自動關閉，玩家回到目前合法可見的對局畫面；玩家自己的手牌可依既有合法流程顯示，但不得新增 `拿取手牌` 或手牌翻面效果。
- **FR-008**: 開局發牌 modal 顯示期間必須阻擋 modal 後方的對局 UI 操作；modal 自動關閉後才恢復後方 UI 操作。
- **FR-009**: 系統必須提供符合目前銀座夜間氛圍的預設卡背，且卡背必須可被後續主題替換或擴充。
- **FR-010**: 預設卡背不得與已揭露角色卡、道具卡或 UI 狀態提示混淆。
- **FR-011**: 偏好減少動態效果的玩家必須能看到短版、低動態或完成狀態的開局呈現，且資訊完整性與一般動畫相同。
- **FR-012**: 玩家在開局動畫期間重連且安全開局進度仍可重播時，系統必須從頭播放開局發牌 modal，且不得重新移除牌、重新發牌或揭露隱藏資訊。
- **FR-013**: 若安全開局進度已標記不再重播，系統不得強制重播完整開局動畫。
- **FR-014**: 開局發牌 modal 必須在手機與桌面尺寸中保持中央牌堆、保留牌與雙方發牌方向清楚可辨識。
- **FR-015**: 開局發牌 modal 不得新增或依賴 skip button、`拿取手牌` 按鈕、手牌翻面、回合抽牌通知或結算畫面改版。

### Non-Functional Requirements

- **NFR-001**: 一般動態模式下，開局發牌演出應在 6 秒內完成，避免阻礙玩家進入對局節奏。
- **NFR-002**: Reduced motion 模式下，開局呈現應在 2 秒內完成或直接顯示完成狀態。
- **NFR-003**: 動畫呈現必須預設保護隱藏資訊，新增或替換卡背時不得需要取得任何卡牌正面資料。
- **NFR-004**: 開局發牌 modal 必須維持既有 mobile-first 遊戲體驗，不得破壞底部區塊導覽或目前合法操作流程。

### Key Entities

- **開局發牌 Modal**: 新對局開始時顯示的專用流程畫面，用於呈現隱藏保留牌與雙方背面起始手牌發牌。
- **背面牌**: 不含卡牌正面資訊的視覺牌，代表尚未揭露的保留牌或起始手牌。
- **隱藏保留牌位置**: 開局中用來表示 1 張本局不使用且未揭露牌的視覺位置。
- **發牌方向**: 先手與後手各自接收背面牌的畫面方向，不代表可見卡牌身分。
- **卡背主題**: 可替換的卡背視覺定義，第一版使用符合銀座夜間風格的預設主題。

## Success Criteria

- **SC-001**: 100% 新對局在取得可重播安全開局進度時，會向玩家顯示開局發牌 modal。
- **SC-002**: 100% 開局發牌 modal 都會呈現 1 張隱藏保留牌、12 張背面起始發牌與完成狀態。
- **SC-003**: 連續 50 次新對局中，開局發牌 modal、卡背與動畫呈現都不包含任何移除牌或起始手牌卡面資訊。
- **SC-004**: 至少 95% 一般開局發牌演出能在 6 秒內完成。
- **SC-005**: Reduced motion 情境下，100% 玩家仍能理解保留牌與雙方起始發牌順序，且呈現時間不超過 2 秒。
- **SC-006**: 在測試的手機與桌面尺寸中，中央牌堆、隱藏保留牌位置、先手方向與後手方向皆可辨識，且沒有主要文字或控制元素重疊。

## Assumptions

- 027 已提供安全的開局進度摘要，且摘要不包含任何卡牌正面資料。
- 028 只負責開局發牌 modal、背面牌與卡背呈現，不改變 server authoritative 牌務結果。
- 若玩家錯過動畫或安全進度已不可重播，恢復到目前合法對局狀態優先於強制重播視覺流程。
- `拿取手牌`、手牌翻面、點擊前遮蔽玩家自己起始手牌與完成後切換到 `手牌&指令` 會由後續 029 規格處理。
- Skip button 行為可在後續動畫控制規格中擴充；本規格不提供 skip 操作。

## Out of Scope

- 新增 `拿取手牌` 按鈕。
- 新增起始手牌翻面動畫或點擊後才顯示手牌的流程。
- 改變 server 開局牌務、手牌分配、移除牌規則或勝負規則。
- 新增 skip button 或定義 skip 後流程。
- 調整回合開始抽牌通知與焦點切換。
- 設計或改版結算畫面。
- 調整大廳 AI 難度文字。
