# Feature Specification: Character Card Coverflow Redesign

**Feature Branch**: `007-character-card-coverflow`  
**Created**: 2026-05-02  
**Status**: Completed  
**Input**: User description: "007-character-card-coverflow-redesign"

## Clarifications

### Session 2026-05-02

- Q: Coverflow 的手動操作方式要怎麼呈現？ → A: 支援滑動/拖曳，並顯示左右切換按鈕。
- Q: 手機版 coverflow 區塊一次要以哪種方式呈現卡片？ → A: 手機中央一張為主，左右露出部分鄰近卡片。
- Q: 桌機版 coverflow 的呈現密度要怎麼定義？ → A: 桌機中央一張為主，左右各顯示約 2 張鄰近卡。
- Q: Coverflow 首尾切換要怎麼處理？ → A: 第一張的上一張切到最後一張，最後一張的下一張切到第一張；左右按鈕與手動滑動都要支援循環。

## User Scenarios & Testing

### User Story 1 - 以 Coverflow 瀏覽七張人物卡 (Priority: P1)

玩家在遊戲房間中可以用手動滑動/拖曳或左右切換按鈕操作 coverflow，瀏覽場上的七張人物卡。人物卡依場上位置魅力值由低到高、由左到右呈現，讓玩家能用新版視覺方式理解目前場上的角色與位置。

**Why this priority**: 這是 007 的核心改版；若沒有 coverflow 與排序，後續卡牌內容重排與掌控狀態顯示都無法正確驗收。

**Independent Test**: 進入 active game room 後，使用滑動/拖曳與左右切換按鈕切換人物卡，確認共有七張人物卡、順序依魅力值由低到高呈現，且不會自動輪播。

**Acceptance Scenarios**:

1. **Given** 玩家進入 active game room，**When** 人物卡區載入完成，**Then** 系統顯示七張人物卡並以 coverflow 方式呈現。
2. **Given** 玩家未操作人物卡區，**When** 等待數秒，**Then** 人物卡不應自動輪播或自行切換焦點。
3. **Given** 玩家使用滑動/拖曳或左右切換按鈕切換人物卡，**When** 目前焦點人物改變，**Then** 玩家仍能辨識每張卡的角色名稱、魅力值與對應 item icon。
4. **Given** 場上七個位置的魅力值為 `2, 2, 2, 3, 3, 4, 5`，**When** 人物卡由左到右排列，**Then** 排列順序應符合該魅力值由低到高的場上位置順序。
5. **Given** 玩家在手機寬度查看人物卡區，**When** coverflow 顯示，**Then** 中央人物卡應作為主要可讀卡片，左右可露出部分鄰近卡片。
6. **Given** 玩家在桌機寬度查看人物卡區，**When** coverflow 顯示，**Then** 中央人物卡應作為主要焦點，左右各可顯示約兩張鄰近卡片。
7. **Given** 玩家位於第一張或最後一張人物卡，**When** 玩家往前或往後切換，**Then** coverflow 應循環到另一端的人物卡，而不是停住或讓最後卡片無法檢視。

### User Story 2 - 人物卡資訊重排為新版卡面 (Priority: P2)

玩家查看人物卡時，卡面不再顯示「未掌控」文字區塊與獨立的「對應道具」區塊；重要資訊集中在左上角斜三角資訊區與底部雙方數量區，讓人物圖像與關鍵資訊更清楚。

**Why this priority**: 卡面內容重排是 coverflow 能否可用的主要視覺需求，必須在不更動遊戲資料與規則的前提下讓卡面資訊更集中。

**Independent Test**: 查看任一人物卡，確認舊的未掌控文字/區塊與獨立對應道具區塊不存在，左上角資訊區與底部雙方數量區完整顯示。

**Acceptance Scenarios**:

1. **Given** 任一人物卡被顯示，**When** 玩家查看卡面，**Then** 卡面不應出現「未掌控」文字或其專用區塊。
2. **Given** 任一人物卡被顯示，**When** 玩家查看卡面，**Then** 卡面不應出現獨立的「對應道具」區塊。
3. **Given** 任一人物卡被顯示，**When** 玩家查看卡面左上角，**Then** 斜三角深色半透明資訊區應顯示角色名稱、魅力值數字與該位置綁定的 item icon。
4. **Given** 任一人物卡被顯示，**When** 玩家查看卡面底部，**Then** 我方數量區應在左側、對手數量區應在右側，兩區各佔底部寬度 50%，總高度約佔卡牌 10%。
5. **Given** 底部雙方數量區顯示文字，**When** 角色名稱或數字較長，**Then** 底部區塊文字不得換行。

---

### User Story 3 - 延續局掌控邊框只在局後狀態顯示 (Priority: P3)

玩家在沒有分出勝負而進入下一局時，可以從人物卡邊框看出上一局結算後已被掌控的角色；但當局進行中，即使某角色暫時滿足掌控條件，也不應提前新增或變更邊框顏色。

**Why this priority**: 掌控邊框是遊戲狀態資訊，若顯示時機錯誤會誤導玩家對當前局勢與局後結算的理解。

**Independent Test**: 建立一個已延續到下一局且已有掌控狀態的房間，確認已掌控人物卡顯示 3px 陣營色邊框；在當局尚未結束前，暫時滿足掌控條件的角色不改變邊框。

**Acceptance Scenarios**:

1. **Given** match 因未分勝負進入下一局且已有角色歸屬我方，**When** 人物卡顯示該角色，**Then** 卡牌邊框應為 3px 我方藍色。
2. **Given** match 因未分勝負進入下一局且已有角色歸屬對手，**When** 人物卡顯示該角色，**Then** 卡牌邊框應為 3px 對手紅色。
3. **Given** 當局尚未結束且某角色暫時滿足某陣營掌控條件，**When** 人物卡重新渲染，**Then** 系統不應新增或變更該角色的陣營色邊框。
4. **Given** 角色尚未由上一局結算確定掌控，**When** 人物卡顯示，**Then** 卡牌不應顯示陣營色邊框。

## Requirements

### Functional Requirements

- **FR-001**: 系統 MUST 在 active game room 以手動操作的 coverflow 呈現七張人物卡，且手動操作 MUST 包含滑動/拖曳與左右切換按鈕。
- **FR-002**: 系統 MUST NOT 讓人物卡 coverflow 自動播放或自動切換焦點。
- **FR-002a**: 系統 MUST 讓左右按鈕與手動滑動都支援首尾循環切換；第一張的上一張為最後一張，最後一張的下一張為第一張。
- **FR-002b**: 左右切換按鈕 MUST 放在人物列表左右兩側，不得集中放在人物列表右上角。
- **FR-003**: 系統 MUST 依場上位置魅力值由低到高、由左到右排列七張人物卡；相同魅力值的位置維持場上位置順序。
- **FR-004**: 系統 MUST 使用目前 match 的七個場上位置與 `ginza` 角色資料顯示人物卡，不得重新抽選角色或改變 match 資料。
- **FR-004a**: 手機寬度的 coverflow MUST 以中央人物卡作為主要可讀卡片，並允許左右露出部分鄰近卡片。
- **FR-004b**: 桌機寬度的 coverflow MUST 以中央人物卡作為主要焦點，並允許左右各顯示約兩張鄰近卡片。
- **FR-005**: 系統 MUST 從人物卡移除現有「未掌控」文字與其專用區塊。
- **FR-006**: 系統 MUST 從人物卡移除現有獨立「對應道具」區塊。
- **FR-007**: 系統 MUST 在人物卡左上角顯示斜三角深色半透明資訊區，覆蓋範圍約為卡牌上邊左側 30% 到左邊上方 40% 的區域。
- **FR-008**: 左上角資訊區 MUST 顯示角色名稱、魅力值數字與該場上位置綁定的 item icon。
- **FR-009**: 系統 MUST 將我方與對手數量區置於人物卡底部。
- **FR-010**: 底部我方數量區 MUST 使用藍色並位於左側；底部對手數量區 MUST 使用紅色並位於右側。
- **FR-011**: 底部我方與對手數量區 MUST 各佔人物卡底部寬度 50%，且底部區塊總高度約佔人物卡高度 10%。
- **FR-012**: 底部我方與對手數量區文字 MUST 不換行。
- **FR-013**: 系統 MUST 只在延續局中，對上一局結算後已掌控的角色顯示 3px 陣營色邊框。
- **FR-014**: 當局尚未結束前，即使角色暫時滿足掌控條件，系統 MUST NOT 新增或變更該角色的陣營色邊框。
- **FR-015**: 系統 MUST 保留既有遊戲規則、計分、角色掌控判定、回合流程、行動流程與 server validation。
- **FR-016**: 系統 MUST NOT 改動手牌排列、贈予互動視窗、競爭互動視窗或 action payload。

### Non-Functional Requirements

- **NFR-001**: 人物卡 coverflow MUST 在桌機與手機寬度都能手動操作並保持主要資訊可讀。
- **NFR-002**: 人物卡改版 MUST 不洩漏隱藏資訊，包含對手手牌、秘密牌與尚未公開的選擇。
- **NFR-003**: 人物卡切換與渲染 SHOULD 不造成可感知的操作卡頓。
- **NFR-004**: 人物卡樣式 MUST 與 Ginza v2 黑紅黑主題背景相容，且不得回復大面積白底視覺。

### Key Entities

- **人物卡**: 場上位置對應的角色視覺卡，顯示角色圖片、角色名稱、位置魅力值、位置 item icon、雙方已打出數量與必要的局後掌控邊框。
- **Coverflow 人物卡列**: 玩家手動瀏覽七張人物卡的展示區，維持七張卡依魅力值排序。
- **左上角資訊區**: 人物卡左上角的斜三角深色半透明區域，承載名稱、魅力值與 item icon。
- **底部數量區**: 人物卡底部的雙欄資訊區，左側顯示我方數量，右側顯示對手數量。
- **局後掌控邊框**: 延續局中用於標示上一局已確定掌控角色的 3px 陣營色邊框。

## Success Criteria

- **SC-001**: 玩家在桌機與手機寬度都能手動瀏覽七張 coverflow 人物卡，且 10 秒內不會發生自動輪播；手機寬度以中央卡為主要可讀卡片並露出部分鄰近卡，桌機寬度以中央卡為主要焦點並左右各顯示約兩張鄰近卡。
- **SC-002**: 七張人物卡依魅力值 `2, 2, 2, 3, 3, 4, 5` 由低到高呈現，相同魅力值維持場上位置順序。
- **SC-003**: 每張人物卡都能在左上角資訊區辨識角色名稱、魅力值數字與 item icon。
- **SC-004**: 每張人物卡底部我方/對手數量區各佔 50% 寬度且文字不換行。
- **SC-005**: 延續局中已掌控角色顯示正確 3px 陣營色邊框；當局進行中暫時滿足條件的角色不提前改變邊框。
- **SC-006**: 實作後既有行動流程、計分、勝負判定與 Socket.IO payload 不變，並通過標準測試與建置驗證。

## Assumptions

- `005-game-data-v2-contract` 已提供 active match 中七個場上位置的角色圖片、名稱、魅力值與 item icon 顯示資料。
- `006-theme-and-room-surface` 已提供 Ginza v2 背景與房間主表層；本 spec 只調整人物卡與人物卡列。
- coverflow 只需要手動操作，不需要 autoplay；首尾循環是手動切換行為，不是自動播放。
- 若同一魅力值有多張人物卡，排序依目前場上位置的穩定順序處理。
- 「我方」與「對手」以目前玩家視角判定，顏色分別固定為藍色與紅色。

## Out of Scope

- 手牌扇形排列、手牌點擊放大或手牌視覺重設計。
- 贈予與競爭互動視窗改版。
- 新增、刪除或修改 action payload、Socket.IO event names、server validation 或遊戲規則。
- 修改 `ginza` 角色池、角色抽選、物品卡生成或 item display data 契約。
- 移除舊資料、版本號調整、CHANGELOG 更新或 release 準備。
