# Feature Specification: 抽牌通知與焦點控制

**Feature Branch**: `030-draw-notification-focus-control`  
**Created**: 2026-05-06  
**Status**: Draft  
**Input**: User description: "030-draw-notification-focus-control"

## Clarifications

### Session 2026-05-06

- Q: 自己抽牌通知在玩家沒有點 `稍後確認` 或 `現在查看` 時，應該停留多久後自動收起並視為 `稍後確認`？ → A: 5 秒後自動收起，視為 `稍後確認`。
- Q: 玩家在 `資訊` 或 `角色` 區收到「自己抽牌」通知時，通知本身是否可以顯示新抽到的卡牌正面資訊？ → A: 通知階段只顯示牌背；切到手牌區後才翻轉顯示卡牌內容並加入手牌。
- Q: 如果玩家在一則「自己抽牌」通知尚未處理時，又收到新的自己抽牌事件，應該如何處理通知與動畫順序？ → A: 正常不預期頻繁連續抽牌；若發生則逐筆排隊處理，前一則完成後才顯示下一則。
- Q: 如果自己抽牌事件到達時正在顯示必要流程，抽牌通知應該何時呈現？ → A: 排隊等待必要流程結束；流程結束後再依當時區塊顯示通知或手牌翻牌。

## User Scenarios & Testing

### User Story 1 - 抽牌不打斷目前查看區塊 (Priority: P1)

玩家在回合開始收到抽牌結果時，如果目前正在查看 `資訊` 或 `角色` 區塊，畫面不應被強制切到 `手牌&指令`。玩家仍會收到清楚的抽牌通知，並可自行決定要稍後再看或立刻切到手牌區查看新牌。

**Why this priority**: 這是 030 的核心體驗問題；若抽牌事件仍會無條件搶走焦點，玩家查看角色盤面或資訊時會被打斷，Phase 5 的「抽牌流程不打斷使用者」目標就沒有達成。

**Independent Test**: 讓玩家停留在 `資訊` 或 `角色` 區塊並觸發自己回合開始抽牌，確認畫面仍停留在原區塊，通知出現且提供 `稍後確認` 與 `現在查看`。

**Acceptance Scenarios**:

1. **Given** 玩家目前停留在 `角色` 區塊，**When** 自己收到回合開始抽牌，**Then** 畫面仍停留在 `角色`，且顯示包含 `稍後確認` 與 `現在查看` 的抽牌通知。
2. **Given** 玩家目前停留在 `資訊` 區塊，**When** 自己收到回合開始抽牌，**Then** 畫面仍停留在 `資訊`，且不會自動展開或聚焦 `手牌&指令`。
3. **Given** 抽牌通知正在顯示，**When** 玩家沒有做任何選擇且通知顯示滿 5 秒，**Then** 通知會自動收起並視為 `稍後確認`，不會切換目前區塊。
4. **Given** 一則自己的抽牌通知尚未處理，**When** 又收到新的自己抽牌事件，**Then** 新事件會排在既有通知後面，等待前一則被查看、稍後確認或 5 秒逾時後才顯示。

---

### User Story 2 - 玩家可立即查看新抽手牌 (Priority: P2)

玩家若在抽牌通知出現後想立刻查看新牌，可以按下 `現在查看`。系統會切換到 `手牌&指令`，並呈現從牌堆抽出一張牌背、拿到手中後翻轉顯示卡牌內容，再加入手牌的效果。

**Why this priority**: 保留玩家主動權的同時，仍要讓想立刻行動的玩家能快速進入手牌操作脈絡。

**Independent Test**: 在 `資訊` 或 `角色` 區塊收到抽牌通知後，按下 `現在查看`，確認畫面切到 `手牌&指令` 並呈現新抽手牌加入手牌的效果。

**Acceptance Scenarios**:

1. **Given** 玩家在非手牌區收到自己的抽牌通知，**When** 玩家按下 `現在查看`，**Then** 畫面切換到 `手牌&指令`，並先呈現牌背抽牌，再翻轉顯示卡牌內容並加入手牌。
2. **Given** 玩家按下 `現在查看`，**When** 新抽牌呈現完成，**Then** 玩家可以依既有合法規則繼續查看手牌與可用指令。
3. **Given** 玩家按下 `稍後確認`，**When** 玩家之後手動切換到 `手牌&指令`，**Then** 直接看到目前合法手牌結果，不再播放補償動畫或重新顯示同一則抽牌通知。

---

### User Story 3 - 已在手牌區時保留既有抽牌節奏 (Priority: P3)

玩家若抽牌發生時已經位於 `手牌&指令`，系統應維持手牌操作脈絡，直接呈現從牌堆抽出一張牌背、拿到手中後翻轉顯示卡牌內容並加入手牌，不需要額外要求玩家在通知中做選擇。

**Why this priority**: 這確保修正非手牌區焦點打斷問題時，不會讓已在手牌區準備操作的玩家多一步。

**Independent Test**: 讓玩家停留在 `手牌&指令` 並觸發自己抽牌，確認焦點仍在手牌區，先看到牌背抽牌，再翻轉顯示卡牌內容並加入手牌，且不出現要求選擇稍後或現在查看的阻擋式通知。

**Acceptance Scenarios**:

1. **Given** 玩家目前停留在 `手牌&指令`，**When** 自己收到回合開始抽牌，**Then** 畫面維持在 `手牌&指令`，並先呈現牌背抽牌，再翻轉顯示卡牌內容並加入手牌。
2. **Given** 玩家目前停留在 `手牌&指令`，**When** 抽牌呈現執行中，**Then** 不會切換到其他區塊，也不會阻擋既有合法的後續操作超過必要呈現時間。

---

### User Story 4 - 對手抽牌與必要流程不洩漏或被打斷 (Priority: P3)

玩家看到對手抽牌時，只應知道對手抽到新牌或手牌張數變化，不應看到對手卡面。若目前有更高優先級流程，例如順序確認、pending interaction、結算、ready check 或開局拿取流程，抽牌通知不得打斷必要流程。

**Why this priority**: 抽牌通知是呈現層功能，不能破壞 hidden information、server authoritative 流程或已存在的必要 UI。

**Independent Test**: 觸發對手抽牌與必要流程中的抽牌事件，確認通知不包含對手卡面資訊，且不會搶走必要流程的焦點。

**Acceptance Scenarios**:

1. **Given** 對手收到抽牌，**When** 本地玩家看到抽牌提示，**Then** 提示不得包含對手卡牌識別、圖片、藝妓、魅力值或文字標籤。
2. **Given** 玩家正在處理必要流程，**When** 抽牌事件到達，**Then** 系統不會把畫面切到 `手牌&指令`，也不會覆蓋或阻擋目前必要流程。
3. **Given** 必要流程期間已有自己的抽牌事件排隊，**When** 必要流程結束，**Then** 系統依玩家當下所在區塊顯示抽牌通知，或在已位於 `手牌&指令` 時直接執行牌背到翻轉加入手牌的呈現。

## Requirements

### Functional Requirements

- **FR-001**: 自己抽牌事件發生時，若玩家目前不在 `手牌&指令`，系統必須維持目前區塊，不得無條件切換或聚焦到 `手牌&指令`。
- **FR-002**: 自己抽牌事件發生時，若玩家目前在 `資訊` 或 `角色`，系統必須顯示抽牌通知，且通知必須提供 `稍後確認` 與 `現在查看` 兩個可啟用選項。
- **FR-003**: 玩家按下 `現在查看` 後，系統必須切換或聚焦到 `手牌&指令`，並先呈現新抽牌牌背，再翻轉顯示卡牌內容並加入手牌。
- **FR-004**: 玩家按下 `稍後確認` 後，系統必須關閉該抽牌通知並維持目前區塊；玩家之後手動進入 `手牌&指令` 時不得重播同一張牌的補償動畫。
- **FR-005**: 若玩家未回應抽牌通知，通知必須在 5 秒後自動收起，且結果必須等同於 `稍後確認`。
- **FR-006**: 若一則自己的抽牌通知尚未處理時又收到新的自己抽牌事件，系統必須逐筆排隊處理；前一則被查看、稍後確認或 5 秒逾時後，才顯示下一則通知或執行下一張牌的呈現。
- **FR-007**: 自己抽牌事件發生時，若玩家已在 `手牌&指令`，系統必須維持目前手牌區脈絡，並先呈現新抽牌牌背，再翻轉顯示卡牌內容並加入手牌，不得要求玩家先回應 `稍後確認` 或 `現在查看`。
- **FR-008**: 自己抽牌通知在 `資訊` 或 `角色` 區顯示時，不得顯示新抽牌的卡牌正面資訊；通知階段只能呈現安全摘要或牌背。
- **FR-009**: 抽牌通知與查看決策必須只影響本地呈現，不得改變實際手牌、回合、行動可用性、抽牌結果、分數或勝負判定。
- **FR-010**: 抽牌通知不得揭露對手手牌、牌堆內容、隱藏保留牌、pending choice 或任何尚未公開的卡牌資訊。
- **FR-011**: 對手抽牌提示必須只呈現安全摘要，例如對手抽到新牌或手牌張數變化，不得顯示對手卡牌識別、藝妓、魅力值、圖片、圖示或文字標籤。
- **FR-012**: 若抽牌事件到達時玩家正在處理必要流程，包含順序確認、pending interaction、結算、ready check、開局發牌 modal 或開局拿取手牌流程，系統不得用抽牌通知搶走該流程焦點，且必須將自己的抽牌通知或翻牌呈現排隊到必要流程結束後再處理。
- **FR-013**: 抽牌通知收起後，玩家仍必須能從目前合法 game state 中看到自己的最新手牌結果；收起通知不得造成已抽牌消失或需要重新同步。
- **FR-014**: 本功能必須維持既有手機優先區塊導覽慣例，且抽牌通知、兩個選項與手牌區呈現不得遮住主要對局資訊或造成主要文字重疊。
- **FR-015**: 本功能不得改變 027 開局牌務、028 開局發牌 modal、029 拿取手牌流程、結算畫面、大廳 AI 難度文字或任何 server authoritative 規則。

### Non-Functional Requirements

- **NFR-001**: 抽牌通知的選項必須可由滑鼠、觸控與鍵盤啟用。
- **NFR-002**: 抽牌通知自動收起時間必須固定為 5 秒，足以讓玩家辨識內容，但不得永久停留或阻擋主要遊戲畫面。
- **NFR-003**: 在一般動態模式下，自己選擇 `現在查看` 或已在 `手牌&指令` 時，新抽牌加入手牌的呈現應在 2 秒內完成。
- **NFR-004**: Reduced motion 偏好下，新抽牌加入手牌可以直接顯示完成狀態，且應在 1 秒內完成可見更新。
- **NFR-005**: 抽牌通知與動畫狀態必須能承受重連或重新渲染；重新回到房間時應以目前合法 game state 顯示結果，不得重複抽牌或顯示 stale 通知。

### Key Entities

- **抽牌通知**: 自己或對手抽牌時顯示的安全提示；自己抽牌且不在手牌區時包含 `稍後確認` 與 `現在查看`。
- **抽牌查看決策**: 玩家對抽牌通知的本地選擇，包含待決、現在查看、稍後確認與逾時自動收起。
- **抽牌通知佇列**: 當多個自己抽牌事件連續到達時的本地呈現順序；正常不預期頻繁發生，但若發生必須逐筆處理。
- **必要流程後抽牌呈現**: 必要流程期間到達的自己抽牌事件，在流程結束後依玩家當下區塊決定顯示通知或直接翻牌加入手牌。
- **新抽牌呈現**: 自己合法可見的新手牌加入手牌區的本地視覺提示；流程先顯示牌背，再翻轉顯示卡牌內容並加入手牌，不得改變 server state。
- **目前區塊焦點**: 玩家正在查看的 `資訊`、`角色` 或 `手牌&指令` 區塊，是決定是否自動呈現手牌動畫的依據。
- **必要流程**: 優先於抽牌通知的既有流程，例如順序確認、pending interaction、結算、ready check、開局發牌 modal 或開局拿取手牌。

## Success Criteria

- **SC-001**: 100% 玩家在 `資訊` 或 `角色` 區收到自己的抽牌事件時，不會被自動切換到 `手牌&指令`。
- **SC-002**: 100% 自己抽牌通知在非手牌區顯示時，玩家可以看到並啟用 `稍後確認` 與 `現在查看`。
- **SC-003**: 100% 點擊 `現在查看` 後，畫面會切到 `手牌&指令`，先顯示新抽牌牌背，再翻轉顯示卡牌內容並加入目前合法手牌。
- **SC-004**: 100% 點擊 `稍後確認` 或通知顯示滿 5 秒自動收起後，玩家留在原區塊，之後手動進入 `手牌&指令` 時不會重播同一抽牌動畫。
- **SC-005**: 100% 多個自己抽牌事件連續到達時，通知或翻牌呈現會依事件順序逐筆處理，不會覆蓋前一則未處理通知。
- **SC-006**: 100% 玩家已在 `手牌&指令` 時收到自己的抽牌事件，會維持手牌區脈絡，先顯示新抽牌牌背，再翻轉顯示卡牌內容並加入手牌。
- **SC-007**: 100% 對手抽牌提示不包含卡牌識別、圖片、藝妓、魅力值或文字標籤。
- **SC-008**: 100% 必要流程期間到達的自己抽牌事件，不會覆蓋必要流程，並會在流程結束後依當下區塊呈現通知或翻牌加入手牌。
- **SC-009**: 在測試的手機與桌面尺寸中，抽牌通知、兩個選項與手牌區呈現皆可辨識且沒有主要元素重疊。

## Assumptions

- 本功能只處理回合開始或既有抽牌事件的前端呈現與 focus 控制；實際抽牌已由 server 完成並同步至合法可見 state。
- 玩家未回應通知時，通知會在 5 秒後自動收起並視為 `稍後確認`。
- 連續多個自己抽牌事件原則上不常發生；若發生，呈現層以逐筆排隊方式處理。
- `現在查看` 是使用者明確同意切換到 `手牌&指令` 的操作，因此可觸發手牌區焦點與新抽牌呈現。
- 自己新抽牌的卡牌內容只在手牌區翻轉後顯示；抽牌通知本身不顯示卡面內容。
- 對手抽牌在本地玩家視角只需要安全摘要，不需要任何卡面資訊或動畫細節。
- 必要流程結束後，抽牌呈現以玩家當下所在區塊為準，而不是以事件到達當下的區塊為準。

## Out of Scope

- 改變 server 抽牌規則、回合流程、手牌所有權、分數或勝負判定。
- 新增或修改 server persisted 抽牌查看狀態。
- 改變 027 開局牌務、028 開局發牌 modal 或 029 拿取手牌流程。
- 新增抽牌歷史紀錄、完整手牌變更 log 或 replay viewer。
- 改版結算畫面。
- 調整大廳 AI 難度文字。
